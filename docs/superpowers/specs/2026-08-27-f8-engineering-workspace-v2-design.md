# F8 Engineering Workspace V2 Design

## Goal

Upgrade the Workbench into a single-page tolerance engineering workspace where F1 image evidence, F2 canonical factor data, F4 dynamic Scenario calculation, F6 capability results, workbook health, ADO governance, and VS Code-hosted conversation remain visible and synchronized.

## Scope decisions

- Use the single-page engineering workspace approach.
- Source Workbook remains immutable.
- LSL and USL are temporary Scenario values. They participate in F4 recalculation, can be reset or saved with the Scenario, and never modify the source Workbook.
- Web and `@ta-assist` share one conversation record; Web answers are generated by a VS Code model host when available.
- Do not add a new Direction selector in this iteration. Keep the existing governed direction behavior and remove the ambiguous visible “reuse Baseline direction” wording from the redesigned UI.
- F7 remains unavailable.

## Layout

The application uses a stable top toolbar and a work-focused responsive grid.

- Toolbar: product name, Workbook identity, read-only state, Worksheet picker, undo/reset/save/export commands. CSS grid tracks prevent title drift and accidental wrapping.
- Evidence workspace: F1 tolerance-path image in a fixed, collapsible evidence pane beside the F2 Factor table on desktop and above it on narrow screens.
- Analysis band: current Scenario metrics, contribution comparison, and specification/range visualization.
- Decision band: workbook health, F6 options, and ADO governance grouped by Part / Subsystem.
- Conversation: collapsible right rail on desktop and drawer on mobile.

## Canonical factor projection

F2 is the canonical display source. The projection preserves this order exactly:

1. F2 worksheet order.
2. F2 factor-table order.
3. F2 row order.

Rows use the stable key `worksheetName + "\0" + tableId + "\0" + sourceRow`. F4 results enrich rows by this key but never reorder or replace F2 identity fields.

The table follows Feature2 report semantics:

- Row
- Factor Description
- Part Name
- Drawing Number
- DIM ID
- Part Category
- Design Nominal
- + Tolerance
- - Tolerance
- Long Term / Safety Factor
- Sigma Level
- Distribution
- Mean
- Tolerance
- One Sigma
- % Contribution to Sigma
- Notes
- Capability result
- Knowledge recommendation

Row, Factor, and Part remain frozen while the remaining columns scroll horizontally. Factor and Part are links that focus and highlight the related F1 image evidence.

## F1 image evidence

F1 image references are registered as session-scoped image artifacts. The browser receives opaque artifact IDs and authenticated inline URLs, never filesystem paths.

The evidence pane provides:

- inline image rendering;
- zoom controls and fit-to-pane;
- full-screen inspection;
- worksheet and source-row context;
- explicit missing-image state;
- highlight feedback when a Factor or Part link is activated.

The artifact endpoint infers the correct image MIME type and serves authorized images inline while retaining path containment, symlink, inode, and session checks.

## Worksheet Scenario and F4 calculation

Scenario editing is worksheet-scoped and accumulates changes across multiple factors.

Editable inputs:

- Design Nominal
- + Tolerance
- - Tolerance
- Additional Mean Shift
- Lower Spec Limit
- Upper Spec Limit

A Scenario request contains factor overrides identified by the stable source key plus optional system-specification overrides. After blur, a 300 ms debounce submits the whole Scenario to the existing governed F4 calculation engine. Stale responses cannot replace newer results.

The response contains all recalculated factor and system metrics:

- factor Mean
- Tolerance
- One Sigma
- Contribution
- system Mean
- RSS
- Cp
- CpkL
- CpkU
- Cpk
- Margin
- Yield
- DPM
- LSL / USL
- statistical and worst-case ranges
- calculation reference and trace references

Baseline remains immutable. Scenario values can be reset or saved as a separate draft.

## Dynamic visualization

Visual semantics:

- Baseline: neutral gray.
- Scenario improvement: engineering green.
- Scenario deterioration: amber or red.
- Values and labels always accompany color.

Contribution visualization renders paired baseline/scenario horizontal bars in F2 row order or a clearly labeled contribution ranking view. The capability view renders baseline and Scenario ranges together.

LSL and USL inputs sit at the corresponding ends of the specification visualization. Editing them updates the graph and all F4-derived capability metrics.

## F6 capability and optimization

The primary capability section follows Feature6 report section 3.5:

- Mean
- Mean Shift
- RSS
- Cp
- CpkL
- CpkU
- Cpk
- Margin
- Yield
- DPM

Two horizontal range bars show:

- 4σ Statistical Range
- Worst-Case Range

Baseline and current Scenario are visually distinguished. F6 candidate options remain a separate governed area so temporary Scenario edits are not presented as accepted F6 recommendations.

## Workbook health

A workbook health section projects Feature2 execution-summary and missing-field evidence:

- worksheet total, ready, and blocked counts;
- missing Factor Description;
- missing tolerance-path image;
- Drawing Number and DIM ID missing totals;
- F0 guidance matched, insufficient, and non-F0 classification counts.

Each finding links to the affected worksheet, row, or image evidence when available.

## ADO governance

F3 governance rows are grouped deterministically by Part / Subsystem across the entire Workbook. Each group shows:

- factor count;
- missing Drawing Number count;
- missing DIM ID count;
- involved worksheets;
- governance state.

Groups expand to the full factor rows. The target panel shows full ADO URL, organization, project, Work Item ID, Owner, Version, preview status, write status, and receipt. Target validation, preview, and final authorization remain Web interactions; VS Code Extension is the only Surface MCP execution host.

## Conversation bridge

The shared SQLite conversation remains authoritative. Web conversation submission creates a model HostAction when a VS Code model host is available. Extension invokes the current available VS Code language model and appends the answer to the same session.

Conversation turns carry:

- worksheet context;
- factor source identity;
- calculation reference;
- related artifact IDs;
- related stage or decision reference.

Conversation append events update Web without refresh. VS Code uses the same projection and unread cursor. If no model host is available, Web shows an explicit waiting/offline state rather than a generic workflow-stage answer.

## Validation

- Projection tests prove F2 field/order fidelity and F4 enrichment by source key.
- Artifact route tests prove image inline rendering, MIME correctness, and containment.
- F4 What-if tests prove multi-factor and LSL/USL recalculation through the governed kernel.
- Web tests prove stable toolbar layout, evidence links, dynamic table/chart updates, workbook health, F6 metrics, ADO grouping, and conversation host states.
- Playwright screenshots cover desktop and mobile, including horizontal table scrolling and assistant drawer behavior.
- Source Workbook hash remains unchanged throughout acceptance.
