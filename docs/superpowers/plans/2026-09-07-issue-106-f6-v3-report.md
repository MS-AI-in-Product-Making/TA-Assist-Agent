# Issue #106 F6 v3 Optimization and Report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace fixed percentage options with a versioned three-step optimization policy and publish a localized, correctly numbered, provenance-free user report.

**Architecture:** Historical F6 v2 remains frozen behind a readable schema. New runs emit F6 v3: deterministic center assessment, ranked tolerance priorities, and F4-verified one-sided specification proposals. Report renderers consume the locked language and validated multimodal interpretation; provenance remains in internal JSON but is removed from every user-facing final report projection.

**Tech Stack:** TypeScript, Zod, deterministic F4 calculation kernel, Node.js Markdown renderers, React, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-07-issue-106-ux-agent-triggering-design.md`

## Global Constraints

- This plan starts only after `2026-09-07-issue-106-multimodal-interpretation.md` is complete.
- New runs require a valid v3 multimodal interpretation for every selected worksheet.
- F4 remains the numeric source of truth; model prose does not compute or approve values.
- New v3 outputs contain no `OP1`, `OP2`, `OP3`, legacy percentage matrix, or replacement arbitrary percentage scheme.
- Contributor advice is ranked and qualitative unless the user separately confirms a concrete Optimization Target.
- LSL/USL proposals are requirement changes, require approval, and never modify the source workbook.
- Historical v2 artifacts remain readable and hash-validated; they are never migrated or overwritten.
- All final-report surfaces remove source/evidence columns; ADO `Worksheet Source` is outside this report rule.
