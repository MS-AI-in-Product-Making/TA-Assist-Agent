# 功能拆分（V1）

> 结构：**Epic -> User Story -> Feature -> Task**。Feature ID 对应项目 Backlog 中现有 ADO Feature；每项任务均可直接实施。

## Epic

**AI Assist Agent（V1）**

> 目标：帮助 ME 工程师将 TA 工作簿快速转化为可靠、可追溯的初步分析结果。助手负责清洗输入、运行与 Excel 一致的计算、用证据突出风险，并持续关联 DIM ID 与实测能力。

## 功能映射

| ID | ADO Feature | 目的 |
|---|---|---|
| F0 | 知识库 | 为所有检查与解读提供受控规则、能力范围和术语。 |
| F1 | TA 报告解析与资产准备 | 识别 TA 工作表、读取数据并收集 Loop 图片。 |
| F2 | 数据清洗 | 在计算前发现缺失项或不合理的 TA 输入。 |
| F3 | 尺寸到图纸关联（DIM ID） | 维持每个因子与图纸尺寸的关联，并治理缺失 ID。 |
| F4 | 方法推荐与计算引擎 | 推荐计算方法并复现与 Excel 一致的结果。 |
| F5 | 数据解读 | 用事实和规则解释风险，不替用户做决定。 |
| F6 | 公差/尺寸链优化 | 比较不同改善方案的量化效果。 |
| F7 | 实测 Cpk 闭环反馈 | 按 DIM ID 回填实测能力数据。 |
| F8 | 用户交互、只读面板与输出 | 为工程师提供完整报告和可见的源证据。 |

---

## F1 到 F2 证据所有权

F1 持有唯一的 worksheet 图片物理 artifact。F2 只携带绑定 content hash 的 F1 `imageReference` 并生成相对链接，不创建 F2 图片副本。F1 同时保存 Response Summary 的原始 `sourceLabel` 以及 `1σ`、`% Cont. to σ` 的公式 cached values；F2 不重命名或重新计算，只负责展示与投影。

## 用户故事 1 - 可靠的初步 TA 结果与摘要

**作为 ME 工程师，当我上传 TA 文件时，我希望助手自动识别所有 TA 工作表、先清洗数据并标记不合理的公差输入，以便快速获得可靠的初步结果和完整报告。**

结果必须包含可快速浏览的 TA 风险摘要。

### 验收标准

1. 自动检测 TA 工作表，并对已选择的多个工作表并行处理（F1）。
2. 检查公差输入的必填字段、规格范围与分布合理性（F2）。
3. 根据因子数量推荐方法，并使用与 Excel 一致的引擎计算（F4）。
4. 输出一份合并解读报告和只读证据面板，其中包含高亮风险摘要（F8）。

### F0 - 知识库

**功能：**维护用于判断 TA 输入或结论是否合理的受控参考数据。

**任务：**

- 维护能力库：公差范围、制程能力、推荐分布和来源等级（T1 实测/PPAP、T2 历史或供应商输入、T3 工程估算、T0 无数据）。
- 维护规则库，包括 CTS = 6 sigma、CTF = 4 sigma 和默认 Cpk 目标 1.33。
- 维护零件类别、子系统和基准名称的术语库（具体边界待定）。
- 为每条库条目记录来源、置信度、生效版本、负责人、变更历史和覆盖范围（后续可继续细化）。
- 将 T0 标记为 `制程能力未知`；在缺少证据时不做可行性声明。

### F1 - TA 报告解析与资产准备

**功能：**在上传工作簿中识别 TA 内容，并准备评审所需的数据和图片。

**任务：**

- 接收一个或多个文件名唯一的 `.xlsx` 文件，并扫描每个工作表以识别支持的 TA 布局。
- 展示识别出的工作簿、工作表、版本/日期和公差链描述，供用户选择。
- 分析前先返回 worksheet options；用户必须基于 workbook content hash 显式确认单个或多个工作表，文件变化后拒绝过期确认。
- 并行处理已选工作表，同时保证每一页都可独立评审。
- 依据语义表头簇定位因子表，不依赖固定列；记录处理时间，并按文件、工作表、版本和日期保留本地调试 JSON。
- 并行提取 Loop 截图，标记源工作表和公差链描述，并随同一次运行记录保存。
- 当自动识别无法处理不规则布局时，提供手动工作表选择（待定）。

### F2 - 数据清洗

**功能：**在计算前检查输入，使初步结果建立在完整、合理的数据上。

**任务：**

- 检查必填字段：因子描述、零件名称、零件类别、设计名义值、公差、长期/安全系数、sigma level、分布以及截面图。
- 将 Response Summary 中的 Lower Spec Limit、Upper Spec Limit 和 Target σ Level 作为必填系统规格，不得从 Suggested Spec 替代取值。
- 名义值或公差缺失时阻塞运行，显示缺失字段清单，要求用户修正并重新上传工作簿。
- 按 worksheet 隔离阻断：ready worksheet 继续并各生成一个 F4 handoff，blocked worksheet 不生成 handoff。
- Drawing Number、Part Number 和 DIM ID 缺失保持非阻断治理语义。
- 将每个公差范围和分布与匹配的能力库条目比较，标记库内和库外结果。
- 检查 DIM ID 与 Part Number 的完整性、重复 ID、格式错误 ID 及供应商到 Microsoft ID 的映射冲突（待定）。当缺失 DIM ID 或 Part Number 时，agent 生成系统级缺失清单，并按 category 分类后触发 ADO 提醒机制。
- 清晰展示所有非阻塞差异；工程师可编辑源 Excel，或在记录例外后继续（待定）。

### F4 - 方法推荐与计算引擎

**功能：**选择适当的一维参考方法，并产出与 TA 工作簿一致的结果。

**任务：**

- 统计因子并识别 CTS/CTF 情况：少于 4 个因子推荐 WC；4–10 个推荐一维 RSS；多于 10 个则标记并转交 DM 团队进行 3D VA 跟进（待定）。
- 始终计算并展示 WC 与 RSS 结果。
- 使用与 Excel 模板相同的公式复现因子级、系统级和能力指标。
- 计算均值、公差、1-sigma、贡献度、Cp、Cpk、Z、DPM 和良率（待定）。
- 使用已批准样例回归验证计算引擎：例如 Cpk 0.74、DPM 约 26,500、FAIL（如后续不再需要，可删除）。

### F8 - 用户交互、只读面板与输出

**功能：**为工程师提供完整、可信的 TA 结果，且不静默修改上传的源数据。

**任务：**

- 在只读证据面板中，以与源工作簿相同的值、布局和单位渲染原始因子表。
- 展示对应工作表证据的 Loop 图片。
- 跨已选择工作表生成一份合并报告，并包含高亮 TA 风险摘要。
- 将每条结论关联到可见的源行或单元格；选择结论时高亮相关证据。
- 保持源数据只读；修改仅通过 Excel 重新上传或经用户确认的系统建议进行。
- 提供报告备份与 ADO 提醒触发入口。

## 用户故事 2 - DIM ID 与图纸治理

**作为 ME 工程师，我希望每个因子都关联图纸范围内的 DIM ID，并生成可审计治理清单，使缺失或冲突标识持续可见且不阻塞 TA。**

### 验收标准

1. 为有效标识建立正式 `(Drawing Number, DIM ID)` 锚点（F3）。
2. 手动上传 `.xlsx` 后，可选地创建或关联 ADO 工作项（F3）。
3. 关联 ADO 时自动绑定负责人；无法解析负责人时，阻塞治理提醒并提示用户（F3）。
4. 仅在用户明确确认已准备的差异后，通过 Surface MCP 更新 ADO Comment 0（F3）。
5. 为每个零件生成尺寸链清单，并按类别打包用于图纸标注（F3）。
6. 无 ADO 或所需能力不可用时，将同一份 confidential 清单保存到本地并继续 TA（F3）。

### F3 - 尺寸到图纸关联（DIM ID）

**功能：**通过稳定的 DIM ID 将每个 TA 因子关联到图纸生命周期；这是标识符关联，而非图纸 OCR 或图片识别。

**任务：**

- 当前契约中 Part Number 等同 Drawing Number，正式键由 `(Drawing Number, DIM ID)` 生成。
- 跨图纸相同 DIM ID 合法；同一规范化 Drawing Number 内重复时标记 `duplicate_conflict`。
- 一位纯数字 DIM ID 为不阻塞 TA 的 `suspected_invalid`；2-4 位纯数字为 `valid`。
- 缺失、可疑或冲突标识进入本地治理清单，TA 继续。
- 允许工程师上传工作簿并创建或关联 ADO 工作项。
- 从 ADO Owner 或 `Request By` 字段解析负责人；无法获取负责人时，阻塞治理提醒并提示。
- 生成每零件尺寸链清单：零件名称、连接编号、DIM ID 和精确源位置。
- 按零件类别和图纸分组清单，使一个图纸包可发送给负责的 Microsoft 和供应商工程师。
- ADO 集成仅依赖 Surface MCP，不要求 Azure DevOps MCP。
- Comment 0 写入严格执行 `prepare -> confirm -> execute`，版本变化时失败关闭；不更新 Description，也不追加普通评论。
- F3 不读取日期、不做截止临近判断，也不运行 scheduler。

## 用户故事 3 - 客观结论与可比较方案

**作为 ME，我希望结论保持客观（事实加规则检查），并提供可比较的优化方案而非强制推荐，以便做出最终工程决策。**

### 验收标准

1. 解读覆盖公差链有效性、能力与规格对比、主要贡献因子、合理公差范围以及设计优化和并列方案（F5，待定）。
2. 缺少关键信息时，显示澄清卡片和假设清单，仅阻塞依赖该信息的结论（F5，待定）。
3. 每项基于规则的结论都关联回知识库证据（F5）。

### F5 - 数据解读

**功能：**将计算结果转化为一致、基于证据的 TA 解读，同时由 ME 评审者保留工程决策权。

**任务：**

- 使用四种陈述类型：`FACT` 表示计算结果，`RULE` 表示阈值检查，`SIGNAL` 表示需要工程关注的事项，`OPTION` 表示并列备选方案（待定）。
- 生成五个必需解读部分：公差链有效性、能力与规格对比、主要贡献因子、合理公差范围以及设计优化和并列方案（待定）。
- 检查公差链闭合、基准链一致性、装配基准面、堆叠起点和加减方向（待定；若缺少图纸依据，则无法完成）。
- 使用规则库评估 RSS sigma、Cpk 和规格窗口可行性。
- 排列主要贡献因子，并解释可测量原因，例如大公差或中段放大（待定）。
- 标记跨子系统、非几何变量和过长尺寸链等结构性风险，但不做无依据结论（待定）。
- 为每条 `RULE` 或能力结论引用知识库条目、版本和覆盖范围。
- 装配基准面、堆叠起点、子系统分类或其他必需证据缺失时，显示澄清卡片和假设清单（待定）。

### F6 - 公差/尺寸链优化

**功能：**展示改善风险的量化方式，但不排序或强制工程推荐。

**任务：** 调整均值 / 调整公差范围

- 检测名义值偏移，并展示均值居中后 Cpk 的改善。
- 使用贡献加权杠杆对公差变更排序，并估算相对成本影响。
- 将所需的 RSS sigma 降幅分配给前两到三个主要贡献因子。
- 对收紧或放宽单个因子执行 What-if 计算，并展示 Cpk 变化。
- 生成两到三个并列反向求解方案：单点收紧、组合主要贡献因子收紧、居中后再收紧。
- 将每个方案与能力库比较；若所需公差不可实现，则显示红色告警，T0 标记为可行性未知。
- 应用 CTS/CTF 规则：CTF 可以展示规格与良率的取舍；CTS 不得放宽规格。

## 用户故事 4 - 实测 Cpk 反馈与持续精度提升

**作为 ME，我希望按 DIM ID 回填实测 Cpk，使系统能够重新计算估算值与实际值的差异，并提高未来分析准确性。**

### 验收标准

1. 按 DIM ID 导入实测 Cpk（F7）。
2. 重新计算实际能力，并展示相对初始估算的差异（F7）。
3. 将匹配能力条目从经验等级升级为实测等级，并保留版本历史（F7）。

### F8 - 实测 Cpk 闭环反馈

**功能：**使用真实实测能力改进当前 TA 结果，并使后续项目的知识库更准确。

**任务：**

- 定义以规范 DIM ID 为键的实测数据架构，包括实测 Cpk、良率、分布、来源和版本。
- 从商定的集中 SharePoint 或平台存储手动导入标准化数据；自动采集属于后续范围（待定）。
- 使用实测数据重新计算 sigma 和实际能力；非正态分布不默认假设正态转换，可采用拟合或蒙特卡洛（待定）。
- 展示初始估算与实测结果，包括真实差异和更新后的公差范围。
- 将显著差异发送给 F6，使工程师比较调整方案。
- 将匹配能力库条目从 T3 经验升级到 T1 实测，并递增版本、保留历史（待定）。

## 范围说明

- 最终工程决策始终由 ME 工程师做出。
- 图纸内容图片识别、3D variation analysis、自动实测数据采集和自动 Excel 回写不属于 V1。
- 为提升速度，多个工作表可并行处理，但仍按页面由人工审核把关。
