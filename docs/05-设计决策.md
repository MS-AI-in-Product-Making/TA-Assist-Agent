# 设计决策（V1）

> 本文记录 V1 的关键权衡，即架构、流程和功能拆分背后的“为什么”。
> 原则：**优先保证确定性、可验证性和可审计性；客观呈现证据并将判断留给用户；存在疑义时停止并询问，绝不编造。**

---

## D1 · 知识库设计（三类库 + 来源等级）

项目的差异化押注在知识库，因此**知识库的完整度和诚实程度直接决定项目能走多远**。V1 收敛为**三类受控知识库**，由人工维护而非自动学习。

### 能力库（Lib 1）

按零件类别组织，每条记录具有三个维度：

| 维度 | 所回答的问题 | 来源 |
|---|---|---|
| 合理公差范围 | 用户输入的公差在**设计层面**是否合理？ | 标准/历史图纸/工程经验 |
| 制程能力（分级） | 该公差在**制造层面**能否真正实现？ | 实测/PPAP/供应商声明 |
| 推荐分布 | 该特征类别应该使用何种分布，以避免默认正态导致 sigma 错误？ | 由制程特性归纳 |

> **合并说明：**原“制程能力库”与“分类公差规范库”在结构上重叠，因此合并为一个库；“推荐分布”同样按类别管理，作为同一张表的列而非独立库。

**来源等级，用于解决实测数据常缺失的问题：**

| 等级 | 数据来源 | 在反向求解/清洗中的行为 |
|---|---|---|
| T1 | 实测/PPAP | 可直接断言可行性 |
| T2 | 供应商声明/历史项目 | 可断言，但标记为“待复核” |
| T3 | 工程经验/标准估算 | 作为默认回退 |
| **T0** | **无数据** | **不主张可行性；标记“制程能力未知，请与供应商确认”** |

**原因：**实际中 T1 常常缺失。来源分级使系统能够优雅降级：有数据时严格，无数据时诚实地标记“未知”，而不是猜测。

### 规则库（Lib 2）

包含 CTS = 6 sigma、CTF = 4 sigma 和默认目标 Cpk >= 1.33 等标准。它们变化缓慢且具权威性，因此需要**版本锁定和变更日志**。

### 术语库（Lib 3，受控词典）

该“受控词典”可**避免模型编造术语或错误分类**。它包含三类查询表：

1. **零件类别词汇表**：固定类别列表（housing/bracket/screw/foam/adhesive/switch/glass/PCBA 等），用于验证零件类别，并作为 Lib 1 的索引键。
2. **子系统词汇表**：为零件打上子系统标签（ME/PCBA/Glass/Display 等），这是识别“跨子系统风险”的前提。
3. **基准词汇表**：基准面的命名规范。

**构建方式：**不使用 AI。从现有 TA 模板中的零件名称提取并整理为平面列表，为每个零件标注所属子系统；新零件出现时再扩展。

**原因：**没有它，“跨子系统”和“类别匹配”就失去意义。它是让其他两个库与结构性风险判断对齐的索引层。

### 维护原则

- 人工维护，不自动学习，避免将错误经验固化。
- 每条记录带有**来源/置信度/生效版本**，从而支持“库内/库外”清洗判断。
- 设定单一负责人、变更日志和公开的**覆盖范围**，例如“Lib 1 覆盖 20 个高频类别中的 6 个”。
- 分布系数常量，例如 Normal = 1、Uniform = 1.732，是**内置引擎常量**，不属于知识库。
- **实测 Cpk 回填 Lib 1 由 F7 处理，见 D8。**

## D2 · 客观解读：陈述证据，将判断留给用户

**不提供指令性建议**，只陈述计算或规则能够证明的内容。机制是为每条陈述标注“断言类型”。

| 标签 | 含义 | 是否可直接断言？ |
|---|---|---|
| `FACT` | 纯计算结果，例如 Cpk = 0.74、A 的贡献为 62% | 可以直接陈述 |
| `RULE` | 与阈值的客观比较，例如 0.74 < 1.33 | 可以直接陈述 |
| `SIGNAL` | 需要工程判断的信号 | 仅标记“值得关注”，不下结论 |
| `OPTION` | 备选路径及其量化后果 | 并列展示、不排序、不推荐 |

**改写示例：**将“建议收紧零件 A”改为“零件 A 的贡献为 62%；若其公差调整为原来的 0.5 倍，Cpk 将从 0.74 变为 1.05（计算结果）。”陈述原因和数字，将行动选择留给用户。

**收益：**系统不再输出无依据判断；验证集只需检查 `FACT` 和 `RULE`，天然可回归测试。

## D3 · SIGNAL 清单（仅标记，不自动下结论）

**跨子系统：**尺寸链跨越具有不同公差习惯、热膨胀和装配方法的工程子系统：

- ME 结构件与 PCBA，例如板厚、元器件高度。
- ME 与 Glass/cover，例如玻璃切割、贴合。
- ME 与显示模组。
- 金属件与塑料件，例如热膨胀差异大。
- 硬件与软性件，例如 foam/adhesive/gasket。

**非几何变量：**涉及物理行为，无法将其视为刚体进行线性叠加：

- 开关/按键行程和压缩。
- Foam 压缩率，具有非线性且受载荷影响。
- 胶层厚度，受固化收缩和压合形变影响。
- Gasket 压缩。
- 螺钉扭矩导致的预载和变形。
- 热膨胀，随温度变化而非仅取决于装配状态。
- 弹性件/卡扣装配形变。

## D4 · 防止编造：存在疑义时停止并确认

**原则：宁可询问，也不编造。**真正的不确定性不是基准“方向”，而是**装配基准面/堆叠起点**。模型可读取数值，却无法仅从表格判断物理尺寸链从哪个面开始或哪些面相配；这类信息存在于图纸或 3D 中，不属于 V1 范围。

机制为**假设清单加确认关卡**：

1. 任何非纯计算推断，例如装配基准面、尺寸链是否闭合、跨子系统归因，只有在输入可提供证据时才可断言。
2. 证据缺失或有歧义时，不猜测，展示带候选项的定向澄清卡片。
3. **局部暂停：**已确认部分照常分析；仅暂停依赖该假设的结论，避免在错误前提上计算。
4. 汇总列出所有假设；用户确认或修正后再发布最终版本。

> **跨子系统归因：**零件所属子系统由 Lib 3 子系统词汇表判断；未找到时同样成为确认项。

## D5 · 规格反向求解（2–3 个并列方案 + 超规格告警）

目标是计算达到 Cpk target = 1.33 所需总 sigma，反推出需要消除的变异，并生成**并列**而非推荐的方案：

| 方案 | 策略 | 适用性 |
|---|---|---|
| 方案 A：单点收紧 | 只收紧最大贡献因子以达标 | 简单；超过制程能力时标记不可行 |
| 方案 B：前 2–3 项组合收紧 | 按贡献比例分摊收紧量 | 更现实，降低单个零件压力 |
| 方案 C：居中加收紧 | 先进行零成本均值居中，再收紧剩余差距 | 存在名义值偏移时最经济 |

每个方案输出：每个零件的新公差、结果 Cpk、**可行性标记（对照 Lib 1 制程能力）**和相对成本估算。

**超规格告警：**当反求公差比该零件类别的可实现制程能力更严时，显示**红色告警**，防止用户盲目收紧公差。

> 目标公差 0.02 已低于此零件类别可实现的 0.05（T2），制程不可实现；强制执行会降低良率并显著增加成本。

对于 T0，标记“可行性未知，请与供应商确认”。

## D6 · 交互设计：只读证据面板，所见即依据

**上传后无需重新打开 Excel。**前提是忠实、只读且不变更地呈现原始 TA 数据，使用户信任可见内容而非黑盒。

**布局：左侧证据，右侧解读。**

- **左侧只读证据：**完整复现 `Example_TA` 因子表，保持数值、布局和单位一致且不可编辑；下方展示提取的 Loop 截图。这是副本视图，不是重新录入。
- **右侧解读：**每条结论引用左侧可见行或单元格；点击结论可高亮左侧关联行。

**三层信任：**看到原始数据，信任自己的观察；看到系统值与 Excel 一致，信任引擎；看到每条解读可追溯，信任结论。

**只读保证及两种改数据路径：**源数据永不被静默覆盖。用户要么编辑 Excel 后重新上传，要么确认系统提出的差异建议。

## D7 · 数据到图纸关联（DIM ID）：主动图纸链路，不做图片识别

领域真正需要的是从 TA 表追溯到图纸尺寸。方案刻意保持轻量：复用 Drawing Number 和 `DIM ID` 将每个因子关联至图纸尺寸。这是**标识符关联，不是 OCR/图片识别**。

机制 A，**关联：**

1. 当前契约中 Part Number 等同 Drawing Number；正式身份由 `(Drawing Number, DIM ID)` 组成，而不是仅使用 DIM ID。
2. Drawing Number 仅在比较时规范化。跨图纸相同 DIM ID 合法；同一规范化图纸内重复时产生 `duplicate_conflict`。
3. 一位纯数字 DIM ID 为不阻塞 TA 的 `suspected_invalid`，2-4 位纯数字为 `valid`，其他非空值为 `needs_confirmation`。缺失或未解决标识保留在治理清单中，TA 继续。

机制 B，**可选 ADO 编排：**

4. **运行入口：**用户手动上传 TA `.xlsx`；创建或关联 ADO 工作项是可选项。工具基于上传文件运行，自动解析 ADO 附件属于后续目标。
5. **负责人绑定：**已关联 ADO 时，先解析 Owner，再回退到 `Request By`；两者均缺失时保存本地且不写入。
6. **仅 Surface MCP：**要求 Work Item 和 Comment 0 的读取/更新能力，不依赖 Azure DevOps MCP。
7. **确认后更新 Comment 0：**准备逐行差异和绑定版本的 confirmation hash，向用户展示并取得明确确认后只执行一次；写入前重读 Comment 0，并在并发变化时失败关闭。
8. **本地回退：**无 ADO、负责人、能力、确认或写入失败时，保存同一份 confidential 治理清单并继续 TA。
9. **无时间编排：**F3 不读取日期、不做截止临近判断，也不运行 scheduler。

**为何纳入范围：**它不需要图片理解、复用已有字段，且是 D8 闭环的硬前提。ADO 治理是可选的：它增加负责人追溯和提醒；本地清单路径确保用户不希望创建 ADO 时仍能继续分析。

**难点：**DIM ID 缺失或同图纸重复、负责人解析、Surface MCP 权限范围，以及防止覆盖并发变化的 Comment 0。

## D8 · 实测 Cpk 闭环：立即看到真实差异，长期提升知识库

当实测良率/Cpk 可获得时，按 `DIM ID` 手动导入并路由到对应因子。该闭环带来两类价值：

- **即时价值：**以真实能力重新计算目标尺寸，使用户看到真实差异、真实公差范围及与初始估算的对比。差异较大时交给 F6 比较调整方案。
- **累积价值：**将匹配的 Lib 1 条目从经验估算 T3 升级为实测 T1，使下一次清洗、解读和优化更准确；回填目标是 F0，闭合 D1 的循环。

**外部前提：实测数据存放位置。**收集和存储真实 Cpk 数据并非本项目可单独控制；需要外部约定，使数据以稳定结构落在单一集中存储中，例如 SharePoint 文件夹或平台系统。没有已知且达成共识的数据源，闭环无法启动。

**范围仅包含读取侧：**

1. 定义以 DIM ID 为键的测量数据架构；从集中存储**手动导入**标准化实测数据，读取实测分布并诚实处理非正态情况下的 sigma 重算。
2. 报告“初始估算与实测”的差异，将 Lib 1 条目从 T3 升级到 T1，并增加版本。
3. **不自动回写 Excel**，将建议规格写回工作簿不属于当前范围。

自动采集实测数据是集中存储和闭环得到验证后的自然后续步骤。

**难点：**DIM ID 治理是硬前提；实测分布通常非正态；集中存储需外部达成并持续维护；先以手动导入验证闭环，稳定后再自动化。

**为何仅做读取侧：**它在推迟高风险回写、自动采集和成本问题的同时，交付“立即看到真实差异、长期更准确”的价值，并让 D1 的来源等级设计被实际使用。

## D9 · F8 是本地 confidential Workbench，而不是聊天记录页

F8 使用一个 loopback Server 和结构化、可恢复的状态机，由 Web、CLI 与 VS Code 共享。同步范围仅包含 TA Assist 自有 turn、decision、stage 和 artifact reference；原生 Copilot history 不作为全局日志读取，也不会持久化。浏览器 cookie/CSRF 与 Extension IPC credential 保持分离。

workbook 与受治理工件始终只读。What-if 只有一个由 F4 支持的临时 Draft，仅 tolerance change 可通过既有 F6 targets 合同晋级。Surface ADO 必须先 validation，再进行独立 write confirmation。F7 在真实owner发布受治理runner前保持 unavailable。

## 设计决策如何塑造功能流程

功能按流程顺序而非优先级排列：**F0 知识库 -> F1 TA 报告解析与资产准备 -> F2 数据清洗 -> F3 尺寸到图纸关联（DIM ID） -> F4 方法推荐与计算引擎 -> F5 数据解读 -> F8 用户交互、只读面板与输出 -> F6 公差/尺寸链优化**，随后由 **F7 实测 Cpk 闭环反馈**将实测 Cpk 回填至 F0。

在方法分支中，`>10` 因子通知 DM 团队跟进 3D VA，而 F4 仍继续计算 WC 和 RSS。F0 知识库与 F5 数据解读决定工具判断质量；F7 闭环决定工具是否能随时间变得更准确。
