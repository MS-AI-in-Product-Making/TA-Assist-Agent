> 本文是 [英文系统架构](01-architecture.md) 的中文映射版，逐项对应 V1 的输入、解析、知识库、DIM ID、可选 ADO 治理、计算、解读、输出和实测闭环。

## 图层映射

| 图层 | Feature | 职责 | 关键说明 |
|---|---|---|---|
| 1 输入 | — | 接收手动上传的一个或多个 `.xlsx` 文件 | 文件名必须唯一；一个文件可包含多个 TA 工作表 |
| 2 工作表选择 | F1 | 自动识别含 TA 内容的工作表，并由用户确认 | 自动识别失败时支持手动选择 |
| 3 解析与提取 | F1 | 读取因子表、提取 Loop 截图、加载知识库 | 保留标准化 JSON、来源标签、版本和处理追踪 |
| 4 知识库 | **F0** | Lib 1 能力库、Lib 2 规则库、Lib 3 术语库 | 人工维护；每项带来源、置信度和覆盖范围；由 F7 回填 |
| 5 DIM ID 关联 | **F3** | 将因子关联到图纸尺寸并生成图纸治理清单 | 当前 Part Number 等同 Drawing Number；正式键为 `(Drawing Number, DIM ID)`。跨图纸相同 DIM ID 合法，同图纸重复产生冲突；一位纯数字标记为 `suspected_invalid`，不阻塞 TA。 |
| 5b ADO 治理 | **F3** | 可选 ADO 关联、负责人解析、Comment 0 更新和本地清单回退 | 仅使用 Surface MCP；每次写入均经过 `prepare -> confirm -> execute`。无 ADO 或所需能力时保存同一份 confidential 清单，TA 继续。F3 不读取日期、不做截止临近判断，也不运行 scheduler。 |
| 6 计算引擎 | F4 | 与 Excel 公式一致的一维计算 | 仅使用经过验证的用户填写字段 |
| 7 输出模式 | F2/F4/F5/F6 | 清洗、方法推荐、客观解读和受治理优化 | `<4` 推荐 WC；`4-10` 推荐 RSS；`>10` 通知 DM 跟进 3D VA，核心引擎仍计算 WC/RSS。F5 负责 baseline evidence 并委派后两章；F6 负责 options、reverse solve、RSS apportionment、feasibility、impact ranking 和联合报告。 |
| 8 闭环 | **F7** | 按 DIM ID 回填实测 Cpk、对比真实差异、回填 F0 | 初期从集中存储手动导入；自动采集和自动回写属于后续范围 |
| 9 交互与输出 | **F8** | 只读证据面板、可引用解读与结构化报告 | 包含 Loop 图片；逐项可追溯与可复现 |

### F8 Workbench 运行架构

F8 是本地 `confidential` 应用，由 loopback Fastify Server、事务 SessionStore/ConversationStore、React Workbench、CLI Agent 入口和 VS Code `@ta-assist` participant 组成。Web、CLI 与 VS Code 只共享 TA Assist 自有 turn 和 session state；原生 Copilot history 仅作当前请求临时上下文，不导入 Store。浏览器使用 cookie/CSRF，Extension Host 通过本地 Node IPC 获取单 action scoped credential。

源 workbook 与 F0-F6 受治理工件保持不可变。每个 session 只允许一个 worksheet-scoped What-if Draft，计算复用 F4 kernel；只有 tolerance change 可通过 `f6-optimization-targets-v1` 晋级。Surface ADO 始终执行 `validate -> independent write`，只有最终写入 receipt 验证成功才可进入 F4。F7 保持 unavailable placeholder，不提供 measured result 控件。

### F5 与 F6 治理边界

F5 直接消费受控的 F0/F1/F3/F4 工件；从 workbook 启动时必须先通过 F2 handoff 门禁。F5 负责 baseline `FACT`/`RULE`/`SIGNAL`、clarification 和可选 v2 图片证据，并保持 v1 只读兼容；详细 F5 报告的第 4/5 章继续标记为 `delegated_to_f6`。

F6 随后精确绑定 F2/F3/F4/F5 roots 与 selected worksheets。它生成保持 band center 的 Top 1 -20% / Top 3 -30% 场景、受 engineering review 门控制的 mean centering、target-Cpk reverse solve、四种 RSS 分配策略、feasibility、Highest Impact 和成本门控 ROI。Supplier、datum 或 cost 缺少绑定证据时保持 `insufficient_evidence`；只有全部 supported ranked options 都有已知正数治理成本时才计算 ROI。联合报告含 workbook summary 和每个 ready worksheet 的十个固定 sections；blocked worksheet 只进入 workbook Input Validation。

直接 CLI 与 trusted app CLI 在受控 publish root 下发布六个 run-scoped artifacts。全部输入输出均为 `confidential` 且源数据只读；不发布 ADO、不访问网络、不写回 workbook。Schema、workbook/worksheet association、identity/hash、staging boundary、atomic rename 和提交后 file identity 门禁均 fail closed。历史 comparison placeholder 作为独立兼容 API 继续返回 `feature_not_available`；真实优化 workflow 已按 [Feature Register](governance/feature-register.md) 标记为 `available`。

> **当前不在范围内：** 自动提取图纸真值、由 DM 负责执行的 3D VA、自动采集实测数据，以及将建议规格自动写回 Excel。
